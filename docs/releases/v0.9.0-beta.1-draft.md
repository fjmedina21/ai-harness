# v0.9.0-beta.1 — release candidate notes

**CANDIDATE — NOT RELEASED.** Local manifests and CLI are aligned to **0.9.0-beta.1**.
A tag and GitHub prerelease require exact candidate hosted CI and final owner approval.
No release date, published package or created tag is claimed.

## What this beta includes

AI Harness is an experimental local-first TypeScript software-engineering harness
for one developer and one GitHub identity. It provides bounded role workflows,
provider-neutral contracts, host-controlled project/tool policies, isolated proposals
and finite supervised repair. It is not certified production autonomous execution.

- Existing OpenAI/Anthropic provider adapters; the engineering/repair CLI uses
  fixture or OpenAI. Anthropic engineering acceptance remains deferred.
- GitHub App OAuth with PKCE and macOS Keychain, independent project authorization
  and exact Personal L2 patch approval: diff review, typed APPROVE, native macOS
  authentication, expiring scoped grant and one-time consumption.
- Separately approved fixed Node validation in a dedicated rootless Podman Machine,
  pinned image, no network/host mounts/engine socket, strict resources and cleanup.
- Durable SQLite operations/repair history, proposal/evidence integrity, CAS/fencing
  and conservative inspection. Unknown effects are not automatically replayed.
- Language-neutral discovery, profile and diagnostic contracts; finite repair with
  cumulative iteration/request/token/time/cost limits and no-progress stops.
- A VitePress portal with local search, contextual navigation, diagrams, keyboard
  operation and sampled tablet/desktop light/dark visual verification.

## Requirements and installation

Source checkout is the supported distribution path; every workspace package remains
private. Use Node.js >=22 (22.13+ for durable SQLite; Node24 is the tested target)
and pinned pnpm **12.21.0**. No npm registry installation is promised.

```sh
pnpm install --frozen-lockfile
pnpm build
pnpm harness --help
pnpm harness version
pnpm test
pnpm docs:check
```

Operational authentication and native confirmation use macOS. A reviewed host-owned
GitHub App/project configuration, existing protected credentials and an exact accepted
preprovisioned Podman profile are required. Linux/Windows native credential adapters
and remote operational execution are not supplied. Model calls require separate
provider/model/budget authorization; login alone grants no paid call or code effect.

## Compatibility, migration and rollback

This prerelease is experimental and pre-1.0. Earlier single-owner migration rejects
legacy Team/account-assignment operational policy; old grants are never converted.
Review [versioning](../VERSIONING.md) and [manual migration](../single-developer-migration.md).
Journals use schema v3; explicitly starting repair adds v4 tables lazily. Read-only
repair inspection does not upgrade a v3 journal. No automatic historical journal
repair or arbitrary database migration is provided.

One inactive synthetic historical journal contained 14 inconsistent approval expiry
bindings and was [archived and explicitly excluded](../phase9c1-historical-journal-exclusion.md).
The current verifier correctly rejects it. Its original data, unknown states and
claims remain preserved; the beta uses a distinct fresh journal. This is not a
compatibility or recovery acceptance for malformed historical authorization state.

Before an authorized upgrade, stop journal users and verify consistent private
backups of the host profile, journal, proposal artifacts/key, receipts and evidence.
For rollback, restore reviewed compatible code and a known-compatible preserved
state only after reconciling effects; do not downgrade schema, change checksums,
restore consumed grants or replay uncertain operations. Source rollback does not
undo filesystem/provider/runtime side effects. The rollback procedure is documented;
a production operational rollback rehearsal is not claimed.

## Known limitations and excluded capabilities

- Operational toolchain acceptance is restricted to exact fixed Node actions;
  manifest detection does not supply installers or other language runtimes.
- Same-UID filesystem races, trusted host/verifier compromise, container/kernel
  vulnerabilities and guest staging mutability remain trust boundaries.
- Filesystem, SQLite, provider and Podman are not one transaction; no external
  exactly-once, universal rollback or production-security guarantee exists.
- Unknown usage/cost retains uncertainty; estimates are not exact billing guarantees.
- Original-source integration, Git-writing agent tools, auto-merge, auto-deployment,
  Team/multiuser operations, remote execution and Phase10 are excluded.

Raw profiles, journals, keys, diffs and native approval records remain private.
The release contains only source and sanitized documentation.
